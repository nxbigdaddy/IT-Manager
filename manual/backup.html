备份

“系统与导入导出” → “服务端一致性备份”调用SQLite在线backup接口，生成在服务器数据目录的 backups 下。返回的是服务器文件名，不是下载到桌面。不要只复制运行中的sqlite3主文件而遗漏WAL。

建议每日及重大变更前备份；将副本按公司政策加密异机保存并测试恢复。按钮不是自动定时备份计划。凭据库与管理员令牌单独受控保管，业务数据库备份不包含DPAPI密钥条件。

离线恢复

  1. 停用/记录所有计划，停止服务并确认相关进程及监听端口关闭。不要覆盖正在运行的数据库。
  2. 保留现库及相关文件，记录恢复目标路径、备份时间与当前源码版本。
  3. 运行离线恢复CLI，只读验证完整性及表结构，再执行明确确认的替换。
  4. 启动后核对业务样本、历史、草稿与发送状态；重新配置无法解密的凭据。
  5. 先核对第三方已发结果，再人工启用周期计划，防止恢复旧备份重复发送。
.venv\Scripts\python.exe -m itmanager.restore "data\backups\示例备份.sqlite3" --target "data\itmanager.sqlite3" --confirm

示例文件名需替换为真实备份。恢复工具会拒绝默认18765端口仍监听的情况、保留恢复前副本并将恢复库中的周期计划全部停用。使用非默认端口时需额外确认实际服务已停；端口检查不能代替操作者检查进程。具体参数可运行 python -m itmanager.restore --help。

若凭据绑定的Windows服务账号或系统密钥不可用，单独复制vault文件不足以恢复，需重新提供密钥。不应把失败的凭据解密绕过为明文存储。

升级与回退

备份 → 停服务 → 更新源码与依赖 → 运行测试与启动检查 → 核对数据和计划 → 恢复服务。数据库版本高于程序时应拒绝启动；回退需兼容源码与备份同时匹配，不可仅降代码。先在独立目录验证备份，不将测试库误替换为生产库。

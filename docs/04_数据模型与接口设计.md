# 04 数据模型与接口设计

## 核心实体
| 实体 | 关键字段/关系 |
|---|---|
| 规划 | ID、周期、目标、责任人、状态、日期、验收 |
| 项目 | 规划ID、业务/技术负责人、阶段、里程碑、预算、验收 |
| 任务 | 项目ID、父任务ID、负责人、优先级、截止、状态、下一步、验收证据 |
| 人员 | 姓名、部门、岗位、主管、邮箱、职责、状态；不保存无关个人信息 |
| 考核 | 人员ID、周期、目标、口径、权重、证据、自评、评价、反馈、复核状态 |
| 运营/治理记录 | 日志、采集、系统、资产、权限、风险、需求、事件、变更、合同、预算、恢复、决策、指标 |
| 提示词 | ID、名称、分类、模板、变量声明、系统约束、版本、启用、历史 |
| 模型配置 | 平台、地址、模型、参数、密钥引用；不能持久化明文Key |
| 渠道 | 类型、名称、机器人/SMTP配置、凭据引用、收件人、启用 |
| 计划 | 周期、时区、时间、周几/月几、类型、范围、模式、渠道、下次执行 |
| 草稿 | 内容、来源、记录ID、提示词/模型版本、状态、修订版本、审批版本 |
| 发送任务 | 幂等ID、计划与槽位、渠道、草稿版本、尝试次数、状态、脱敏结果 |
| 审计 | 时间、操作者、动作、对象、变更摘要/受控历史引用；避免复制敏感正文 |

## 通用规则
ID稳定且不可复用；创建/更新为UTC ISO时间；业务日期为YYYY-MM-DD；界面按选定时区展示。金额使用十进制字符串并记录币种，不能浮点混算不同币种。空值表示未采集，不等于0。引用对象存在性、父任务环、完成证据、日期顺序在服务端验证。

版本整数实现乐观锁。删除优先归档/取消，引用对象不直接硬删除。审计与业务保存同一事务。审批后正文改变需撤销审批；发送保存不可变内容快照或版本哈希。

## 存储设计
原型已有通用records（module＋JSON）、objects配置、deliveries、audit。首版可保留扩展字段JSON，但必须增加结构化验证、索引/分页、关系校验和迁移版本表；核心任务状态及关联不能只依赖自由文本。

数据库升级使用有编号迁移、升级前备份、事务执行；失败不启动业务。恢复前停服务，验证备份和schema版本，保留当前副本。附件首版以受控证据链接为主，不支持任意服务器路径供客户端下载或发送。

## API设计
统一Bearer认证；远程只经HTTPS。错误采用稳定错误码＋中文安全消息；400校验、401认证、404缺失、409版本冲突、413过大、429限流、503外部依赖不可用。原型尚未完全按此区分。

| 方法/资源 | 语义 |
|---|---|
| GET /health、/schema | 认证后服务状态、表单定义 |
| GET /records | 模块/关键词/责任人/日期/状态筛选、分页（分页待实现） |
| POST /records/{module} | 新增或带ID/version保存；原型已存在 |
| GET/POST /objects/{kind} | 渠道、模型、提示词、计划；后续替换为类型化校验 |
| POST /reports | 范围生成草稿，不自动批准 |
| POST /ai/generate | 明确授权的选定记录＋提示词＋变量，生成草稿 |
| POST /drafts/{id}/review | 编辑/批准指定版本 |
| POST /send | 渠道＋批准草稿版本＋幂等请求ID；结果可查询 |
| GET /deliveries、/audit、/ai/calls | 脱敏记录 |
| POST /backup、GET /export | 服务端一致性备份、业务导出 |
| 后续专用接口 | 连接测试、凭据写入、导入预览/提交、重试确认、看板、历史版本 |

## 导入导出
Excel导入：用户选文件→读取表头映射→预览新增/更新/错误→用户确认→事务写入或报告失败；禁止按行号默默覆盖。已有管理工作台字段需显式映射，不假设名称完全一致。JSON导入需schema版本检查。导出不含凭据，考核/权限单独确认，Excel文本防公式注入。保存导入批次与结果，可追溯。

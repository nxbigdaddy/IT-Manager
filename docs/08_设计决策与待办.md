# 08 设计决策与待办

## 已确定决策
| 编号 | 决策 | 原因 |
|---|---|---|
| ADR01 | PySide6 Windows桌面 | 用户明确要求；不是Tkinter/Web UI |
| ADR02 | 本地优先，服务与桌面可同机独立运行 | 用户要求优先本地GUI完成度；保留常开服务器调度 |
| ADR03 | 首版SQLite | 用户指定；无需安装额外数据库 |
| ADR04 | 数据库配置与仓储适配接口 | 预留其他数据库入口，业务/GUI不耦合SQL；其他后端未实现时明确拒绝 |
| ADR05 | 三平台群机器人＋SMTP | 用户选择，不扩展通讯录和收邮件 |
| ADR06 | AI草稿、人审执行 | 避免幻觉和未经批准的任务/考核/发送 |
| ADR07 | 源码＋BAT，不编译 | 用户明确要求；HTML手册便于后续CHM |
| ADR08 | 单可信管理员暂定 | 多人认证/权限未确认；不允许假装有员工隔离 |

## 数据库扩展约定
配置项DB_BACKEND默认sqlite、DB_URL/路径由配置解析；定义Repository接口覆盖记录查询保存、配置、审计、发送幂等、事务、迁移和备份能力。SQLiteRepository为首个实现。PostgreSQL/MySQL未来通过独立适配及迁移实现；启动时若指定未支持后端，返回清晰错误，不静默回退SQLite。备份接口按后端定义能力，不能复用SQLite文件复制到其他数据库。

## 初始原型差距（历史记录）

下列记录为编码前的差距快照。v0.1.0已完成PySide6、仓储接口、模板变量、业务校验、CAS审核/快照、导入/看板、DPAPI凭据、配置白名单及调度错误可见性；分页采用客户端每页100条，服务端分页仍为后续扩展。最终测试见[交付测试报告](<09_测试报告与交付状态.md>)。

- 桌面GUI尚未实现，PySide6依赖待验证。
- 现有Store为SQLite具体类，需仓储接口与配置工厂。
- AI默认模板用content变量，服务原型只注入records，需统一兼容并测试。
- 通用文本台账未完成引用、状态流转、数值和考核业务校验。
- 服务原型有基础汇报、调度和发送，但审批版本/发送快照、导入、分页、看板、重试和GUI凭据管理待完善。
- 原型安全键名拦截应改成类型化配置白名单，避免误拦截正常字段或漏嵌套凭据。
- 调度错误不能静默吞掉，需可见心跳和错误状态。
- 服务器尚未运行，真实平台尚未联调；适配模块mock测试不代表完整应用通过。

## 推进原则
先文档/Git→本地SQLite与完整PySide6操作闭环→集成调度可靠性→本机整体测试/BAT/HTML手册→可选远程部署。独立子任务可并行，但不能多个代理同时修改同一文件。所有变更同步更新日志。

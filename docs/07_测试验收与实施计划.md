# 07 测试验收与实施计划

## 阶段及门禁
1. **M0设计基线**：docs齐全、更新日志、本地Git；GUI确定PySide6。
2. **M1业务与数据**：类型校验、关联、任务和考核状态、分页、导入导出、审计及备份测试。
3. **M2集成与自动化**：通知/邮件/AI适配、调度、审批版本、幂等及恢复；模拟测试通过。
4. **M3完整桌面**：所有确认范围的模块可操作，结构化配置，后台请求，错误处理；不得仅展示占位页面。
5. **M4闭环与交付**：BAT启动、GUI冒烟、服务闭环、HTML手册、测试报告、Git干净可追溯；无EXE编译。

用户授权自主持续迭代，不需要一般细节确认；涉及真实外部发送、生产部署及不可得凭据时不越权、不伪造结果。

## 整体闭环样本
使用隔离临时数据和虚构人员：建人员→规划→项目→父子任务→工作记录→阻塞/风险→决策→交付证据→验收→考核证据/评价→生成周报→AI润色草稿（mock）→审核→机器人/邮件发送（mock）→重复拦截→周期生成→故障恢复→导出→备份恢复核对。

单元测试不能代替闭环；服务测试不能代替GUI测试。测试数据库、真实工作数据库分离。任何失败应修复或明确记录，不能只报告通过数量。

## 结果声明
测试报告分别列：单元、服务集成、GUI自动化/人工检查、本机BAT冒烟、真实外部联调、服务器部署。后两者没有凭据/环境时标未执行，而非通过。记录命令、环境、日期、用例数、失败/跳过及证据。使用手册说明相同边界。
